# Описание нормативных документов платформы Auc

В данной директории содержатся официальные политики и регламенты цифровой аукционной платформы **Auc**.

Платформа представляет собой аукцион **исключительно цифровых объектов** (изображения, 3D-модели, аудио, видео, документы, архивы), функционирующий на базе **виртуальной (ненастоящей) валюты**. Все балансы, ставки и операции являются игровыми/условными, не имеют эквивалента в реальных деньгах и не могут быть монетизированы. Платформа не несёт финансовой ответственности перед пользователями.

---

## 1. Архитектура документов в базе данных

Документы хранятся в таблице PostgreSQL `documents`, а факты согласия пользователей фиксируются в таблице `user_consents`:

```postgresql
create table documents (
    id bigint generated always as identity primary key,
    name text not null,
    version text not null default '1.0',
    is_major bool not null default true,
    text text not null,
    published_at timestamptz not null default now(),
    superseded_at timestamptz default null,
    unique (name, version)
);
create unique index on documents (name) where superseded_at is null;

create table user_consents (
    id          bigint generated always as identity primary key,
    document_id bigint not null references documents(id),
    user_id     uuid not null references users(id),
    action      text not null check (action in ('granted','withdrawn')),
    granted_at  timestamptz not null default now(),
    ip          inet,
    source      text not null
);
create index on user_consents (user_id, document_id, granted_at desc);
```

### Принципы версионирования:
1. **Активный документ**: запись с `superseded_at IS NULL`. Уникальный частичный индекс гарантирует ровно одну активную версию документа с данным `name`.
2. **`is_major = true`**: критическое обновление. Пользователь блокируется от совершения действий на платформе (создание лотов, ставки, операции с балансом) до тех пор, пока явно не подтвердит согласие с новой версией.
3. **`is_major = false`**: минорные изменения (орфография, стилистика, уточнения). Повторное блокирующее согласие не требуется, документ заменяется «прозрачно».
4. **Архивация старой версии**: при выходе новой версии старой записи проставляется `superseded_at = now()`.

### 1. `terms-of-service.md` — Пользовательское соглашение (Terms of Service)
* **Имя в БД:** `terms-of-service`
* **Версия:** `1.0`
* **Флаг `is_major`:** `true`
* **Ключевые положения:**
  * Базовый контракт между пользователем и платформой.
  * Описание сервиса: создание аукционов, размещение цифровых лотов, совершение ставок.
  * Прямой запрет на использование реальных денег: вся валюта виртуальная и не подлежит обмену/выводу.
  * Требования к аккаунту: возраст от 13 лет, один аккаунт на пользователя, безопасность учетных данных.
  * Права платформы: модерация, удаление лотов и медиафайлов без предварительного уведомления, блокировка пользователей.
  * Полный отказ от гарантий («AS IS») и ограничение финансовой ответственности.
* **Когда запрашивается:**
  * **Обязательно при регистрации аккаунта**: чекбокс с прямой ссылкой на текст соглашения. Регистрация без согласия невозможна.
  * **При мажорном обновлении (`is_major = true`)**: блокирующий модальный диалог при следующем входе в систему.
* **Ссылка на файл:** [terms-of-service.md](file:///C:/Users/Chadaev/GolandProjects/Auc/migrations/documents/terms-of-service.md)

### 2. `privacy-policy.md` — Политика конфиденциальности (Privacy Policy)
* **Имя в БД:** `privacy-policy`
* **Версия:** `1.0`
* **Флаг `is_major`:** `true`
* **Ключевые положения:**
  * Перечень собираемых данных: имя пользователя, адрес электронной почты, хеш пароля, загруженный аватар, история действий (лоты, ставки), технические данные (IP-адрес, User-Agent, cookie).
  * **Отсутствие финансовых данных**: платформа принципиально не собирает номера банковских карт, счетов и платежных реквизитов, так как реальные платежи отсутствуют.
  * Хранение медиафайлов: изображения и аватары хранятся в S3-совместимом хранилище.
  * Запрет на продажу персональных данных третьим лицам.
  * Права пользователя: доступ к данным, исправление, удаление аккаунта (право «на забвение»).
* **Когда запрашивается:**
  * **При регистрации аккаунта**: обязательный чекбокс ознакомления с политикой обработки персональных данных.
  * **В подвале сайта (Footer)**: доступен для чтения любому посетителю без авторизации.
  * **При мажорном обновлении**: обязательное повторное подтверждение.
* **Ссылка на файл:** [privacy-policy.md](file:///C:/Users/Chadaev/GolandProjects/Auc/migrations/documents/privacy-policy.md)

### 3. `virtual-currency-disclaimer.md` — Дисклеймер о виртуальной валюте (Virtual Currency Disclaimer)
* **Имя в БД:** `virtual-currency-disclaimer`
* **Версия:** `1.0`
* **Флаг `is_major`:** `true`
* **Ключевые положения:**
  * **Фундаментальный юридический щит платформы.**
  * Валюта платформы не является деньгами, платежным средством, криптовалютой, цифровым финансовым активом или ценной бумагой.
  * Баланс пользователя — это исключительно числовое поле в базе данных, предназначенное для игровой механики аукциона.
  * Платформа оставляет за собой право в любой момент сбрасывать, корректировать или аннулировать балансы без компенсации.
  * Никакие возвраты (refunds) невозможны, так как реальные деньги не принимались.
  * Налоговые обязательства отсутствуют, так как экономическая выгода не возникает.
* **Когда запрашивается:**
  * **При первом входе на сайт / регистрации**: отдельный акцент или обязательный чекбокс: *«Я понимаю, что валюта на сайте виртуальная и не имеет реальной ценности»*.
  * **При первом начислении / пополнении тестового баланса**: информационное предупреждение.
  * **При первой ставке на лот**: всплывающее подтверждение, напоминающее о виртуальности ставки.
* **Ссылка на файл:** [virtual-currency-disclaimer.md](file:///C:/Users/Chadaev/GolandProjects/Auc/migrations/documents/virtual-currency-disclaimer.md)

### 4. `auction-rules.md` — Правила проведения аукционов (Auction Rules)
* **Имя в БД:** `auction-rules`
* **Версия:** `1.0`
* **Флаг `is_major`:** `true`
* **Ключевые положения:**
  * Механика аукциона: стартовая цена (`start_amount`), минимальный шаг ставки (`min_step`), фиксированное время начала и окончания.
  * **Безотзывность ставок**: любая ставка является окончательной, её нельзя отменить или уменьшить.
  * Определение победителя: побеждает максимальная ставка на момент наступления `ends_at`.
  * Запрет недобросовестной конкуренции: разгон цены (shill bidding), использование нескольких аккаунтов для манипуляции ставками, сговор участников.
  * Право администрации отменить аукцион, аннулировать подозрительные ставки или завершить торги принудительно.
* **Когда запрашивается:**
  * **При создании лота/аукциона продавцом**: модальное окно перед публикацией лота с подтверждением согласия с правилами торгов.
  * **При первой ставке покупателя**: подтверждение понимания того, что ставка безотзывна.
  * **При регистрации**: входит в общий пакет обязательных правил.
* **Ссылка на файл:** [auction-rules.md](file:///C:/Users/Chadaev/GolandProjects/Auc/migrations/documents/auction-rules.md)

### 5. `content-policy.md` — Политика в отношении контента (Content Policy)
* **Имя в БД:** `content-policy`
* **Версия:** `1.0`
* **Флаг `is_major`:** `true`
* **Ключевые положения:**
  * Требования ко всем загружаемым материалам (лоты, описания, картинки, 3D/видео/аудио, аватары, имена).
  * **Категорически запрещено:**
    * Противоправный контент любого рода;
    * Порнография, интимные материалы (NSFW);
    * Разжигание ненависти, дискриминация, насилие и жестокость;
    * Вредоносное ПО (вирусы, трояны, эксплойты);
    * Нарушение авторских прав (чужой арт без лицензии, пиратский контент);
    * Обманные и вводящие в заблуждение описания лотов;
    * Публикация чужих персональных данных (доксинг);
    * Попытки продажи реальных вещей под видом цифровых или вывод сделок в реал.
  * **Право на одностороннее удаление**: платформа вправе немедленно удалить лот, скрыть картинку или заблокировать контент без объяснения причин и без компенсаций.
  * Прогрессивная шкала санкций: Предупреждение -> Удаление контента -> Временная заморозка -> Перманентный бан.
* **Когда запрашивается:**
  * **При загрузке файлов в S3 / создании лота**: предупреждение над формой загрузки о недопустимости запрещенного контента.
  * **При регистрации**: в рамках общего пакета правил.
* **Ссылка на файл:** [content-policy.md](file:///C:/Users/Chadaev/GolandProjects/Auc/migrations/documents/content-policy.md)

## 4. Рекомендации по интеграции в Frontend и Backend

### 4.1 Форма регистрации (Registration Flow)
На странице регистрации пользователю должен предлагаться блок согласий:
1. Чекбокс 1 (Обязательный):
   > *«Я принимаю [Пользовательское соглашение](file:///C:/Users/Chadaev/GolandProjects/Auc/migrations/documents/terms-of-service.md), [Политику допустимого использования](file:///C:/Users/Chadaev/GolandProjects/Auc/migrations/documents/acceptable-use-policy.md), [Правила аукционов](file:///C:/Users/Chadaev/GolandProjects/Auc/migrations/documents/auction-rules.md) и [Политику в отношении контента](file:///C:/Users/Chadaev/GolandProjects/Auc/migrations/documents/content-policy.md)»*
2. Чекбокс 2 (Обязательный):
   > *«Я согласен с [Политикой конфиденциальности](file:///C:/Users/Chadaev/GolandProjects/Auc/migrations/documents/privacy-policy.md)»*
3. Чекбокс 3 (Обязательный акцент):
   > *«Я подтверждаю, что ознакомлен с [Дисклеймером о виртуальной валюте](file:///C:/Users/Chadaev/GolandProjects/Auc/migrations/documents/virtual-currency-disclaimer.md), понимаю, что все ставки и балансы на сайте являются виртуальными, не имеют реальной денежной ценности и платформа не несёт финансовой ответственности»*

При нажатии «Зарегистрироваться» бэкенд в единой транзакции создает пользователя и добавляет записи в `user_consents` для всех активных документов:
```sql
insert into user_consents (document_id, user_id, action, ip, source)
select id, $user_id, 'granted', $client_ip, 'registration_form'
from documents
where superseded_at is null and is_major = true;
```

### 4.2 Проверка актуальности согласий (Middleware / Guard)
В API предусмотрена проверка: имеет ли пользователь актуальные согласия по всем активным документам с `is_major = true`:
```sql
select d.id, d.name, d.version
from documents d
where d.superseded_at is null
  and d.is_major = true
  and not exists (
      select 1
      from user_consents uc
      where uc.document_id = d.id
        and uc.user_id = $user_id
        and uc.action = 'granted'
  );
```
Если запрос возвращает хотя бы одну строку, фронтенд перенаправляет пользователя на полноэкранное окно подтверждения обновленных документов перед предоставлением доступа к функционалу ставок и торгов.
