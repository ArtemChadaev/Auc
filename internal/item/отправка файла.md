```mermaid
sequenceDiagram
autonumber
actor User as Клиент
participant API as ItemHandler / Service
participant VK as Valkey
participant S3 as S3 Storage
participant DB as Postgres

    User->>API: POST /api/upload/url (file_size, sha_256_hex, filename)
    API->>VK: Проверка: нет ли у пользователя активной загрузки
    API->>DB: Проверка: нет ли такого хеша в s3 (SELECT EXISTS)
    API->>S3: Генерация Presigned PUT URL ("tmp/<uuid>")
    API->>VK: Запись pending-состояния и блокировки пользователя
    API-->>User: 200 OK (url, key)

    User->>S3: Прямой HTTP PUT бинарных данных файла
    S3-->>User: 200 OK

    User->>API: POST /api/upload/confirm (Заголовок X-Upload-Key: <uuid>)
    Note over API,S3: Проверка «капли»
    API->>S3: HeadObject: проверка совпадения размера
    API->>S3: DownloadRange (bytes 0-511): чтение первых 512 байт
    API->>API: Валидация соответствия расширения и MIME-типа
    API->>API: Проверка лимитов (видео <= 1 ГБ, архивы <= 5 ГБ)
    API->>VK: Статус -> "processing"
    API-->>User: 202 Accepted (принято к обработке)

    Note over API,DB: Фоновая обработка (воркер-пул N=5 параллельных задач)
    API->>S3: Стриминговое скачивание полного файла
    par Хеширование и метаданные
        API->>API: Вычисление реального SHA-256
    and
        API->>API: Поточная генерация Metadata (ffprobe, blurhash, gltf, pdfcpu...)
    end
    API->>S3: Move ("tmp/<uuid>" -> "<uuid>")
    API->>DB: INSERT INTO s3 (id, hash) + INSERT INTO items (...)
    API->>VK: Статус -> "completed", сохранение Item и Metadata, снятие блокировки

    loop Каждые 5 секунд
        User->>API: GET /api/upload/status?key=<uuid>
        API->>VK: Получение статуса
        API-->>User: 200 OK (status: completed, item: { ... metadata: ... })
    end

    User->>API: GET /api/item/{id}/download
    API->>API: Проверка: владелец (owner_id == uid)
    API->>VK: Проверка суточного лимита (SetNX 1 раз в день на uuid+uuid файла)
    API->>S3: Генерация Presigned GET URL с оригинальным filename
    API-->>User: 200 OK (url для скачивания)
```

При ошибке в POST /api/upload/confirm (Заголовок X-Upload-Key: <uuid>), Проверка «капли», удаляется в s3 если причина связанна с пользователем. Если изза сервера (internalError, все 500), то пользователь может заного попытатся отправить этот запрос
При ошибке в GET /api/upload/status?key=<uuid>, Если ошибка связанна с пользователем опять же удаляется из s3, если нет и ошибка сервера то может еще пытатся пока не получит 400 или 200
